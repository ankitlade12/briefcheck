Independent AI-agent functional review — not human validation

Scope: saved workspace / reopen, decisions after local rerun, concurrent collaboration, reviewer permissions, templates, manual interpretation decisions, exported source versions. Inspected App.tsx, server/index.mjs, storage.mjs, review-state.mjs and export.mjs. Used a fresh isolated port5174 server and in-memory database; no provider calls or publication. Implementation changes were made by the parent agent, not this reviewer.

Initial executed results: 7 probes, 4 passed and 3 failed (independent-agent.functional-results.json). Three concrete failures:
1. App decision() sent every decision in an already-saved workspace to the server, even for new local runs not persisted there. API returned 400 and local decision was not saved.
2. Decision responses advanced local saved.revision while leaving a stale full workspace in memory. After an editor changed title, owner with stale local data posted a decision, adopted revision 3, then saved original title successfully. This overwrote the editor's title despite optimistic concurrency. Executed, not merely inferred.
3. Correcting a predicate from <=120 seconds to <=60 seconds with immutable source versions preserved an accepted finding with needsReview:false. carryReviewState checked only source versions. Executed through the same assembleReview/carryReviewState path used by the UI.

Fix retest: 7/7 focused API/engine checks passed (independent-agent.functional-retest-results.json). The updated UI sends revision with persisted-run decisions. A stale decision now returns 409, and subsequent stale save also returns 409; editor title survives. Changed interpretation now carries needsReview:true. New-run decisions are deliberately not sent until the local review is saved. Server appropriately still rejects an unknown run; this API assertion is not itself a UI pass.

Actual browser verification separately passed (independent-agent.functional-browser-results.json): authenticated browser -> sample materials -> review -> save privately -> rerun -> accept finding -> explicit local-save reminder -> save -> API inspection confirms two runs and accepted decision in latest run. Zero browser page errors. Browser runner: tests/functional-audit-browser.mjs. Compatible Chromium executable supplied via CHROME_PATH. Initial attempts hit missing default browser and a test selector matching the button name without its arrow; these were test-environment/selector issues, not product findings.

Other successful checks: saved/reopened run equals original immutable snapshot; reviewer PUT is 403 while persisted-run decision is allowed; private template sources round-trip unchanged; export retains hashes/version history, includes text on opt-in, and omits raw version text otherwise; HTML contains the source hash.

Additional correction limitation identified during inspection was addressed by parent: interpretation editor previously could not change items and could mark an empty deliverable set supported. Current App.tsx includes items in correction data and requires a nonempty short-string item set for criteria/deliverables. This patch was code-inspected, not independently browser-executed in this pass.

Remaining scope limits: bounded functional tests, not comprehensive browser coverage of every control. Template restore itself was code-inspected (fresh IDs, reset runs/revisions/clarifications/saved/historical); API round trip was executed. Reviewer rerun-before-save now has explicit editor-save prerequisite but that reviewer browser message was not separately exercised. Full scenario reruns were covered in existing project tests rather than duplicated here. No live-provider, multilingual, human usability, load, or deployment assessment. Decision API revision remains optional for callers; the application sends it. Guarantees above concern current single-process local deployment and tested application flow.
