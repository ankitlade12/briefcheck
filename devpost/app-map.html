BriefCheck / app map

Follow a real action: make the three-minute boundary consistent without losing the original evidence.

Source text→Validated extraction→Numeric example→Organizer edit→Retest + export
1. Review instructions

src/App.tsx sends the current source cards to POST /api/reviews. server/analysis.mjs validates size, creates SHA-256 snapshots, and uses either the local parser or the configured model. Model quotes must match exactly.

2. Test 180 seconds

src/engine.mjs evaluates duration ≤ 180 and duration < 180 in ordinary code. The difference is reproducible without another model call. Recommendations retain advisory wording.

3. Edit and rerun

src/review-state.mjs carries saved facts into the new source versions. Missing evidence makes a scenario stale rather than passing. Prior runs retain their original predicates and evidence. src/export.mjs escapes the printable report.

Expanded workspace

server/storage.mjs: private SQLite persistence and password hashing. server/index.mjs: owner/editor/reviewer authorization, request limits, templates and explicit webhook exports. server/imports.mjs: bounded public HTTPS and text-PDF ingestion.

A practice to reuse

Before implementing a claimed correction, write one boundary example and one example that should remain unchanged. Keep the original evidence and rerun the same facts. This catches the difference between a successful correction and merely hiding the problem.

This is an offered practice, not a claim about the user's learning. Hands-on review and reflection remain the user's choice.
